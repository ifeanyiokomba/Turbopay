# Plan: Add Error Boundaries to Components

## Context

This is a Next.js 16 + React 19 SPA. All 48 views render client-side through `app-shell.tsx`'s `renderView()` switch statement. Currently, if any view throws a render error, the entire app crashes to the root `error.tsx` — losing all UI state. There are no React class-based error boundaries anywhere in the codebase.

## Approach

Create a reusable `ErrorBoundary` component and wrap the view rendering layer in `app-shell.tsx` so each view is isolated. A crash in one view (e.g. Admin → System Health) won't kill the dashboard or sidebar.

### Files to create

1. **`src/components/ui/error-boundary.tsx`** — Reusable React class component
   - `getDerivedStateFromError` → captures error, sets `hasError: true`
   - `componentDidCatch` → logs to console.error (Sentry is already in the project but we log here for visibility)
   - Renders a branded fallback card matching the existing `error.tsx` style (AlertTriangle icon, "Something went wrong", "Try again" button calling `reset()`, "Go home" button)
   - Accepts optional `fallback` prop for custom error UI
   - Uses shadcn `Button` and lucide `AlertTriangle` (already in the project)

### Files to modify

2. **`src/components/turbopay/app-shell.tsx`** — Wrap `renderView()` output
   - Import the new `ErrorBoundary`
   - Wrap `{renderView()}` at line 512 with `<ErrorBoundary key={view}>`
   - The `key={view}` is critical: it forces the boundary to reset when the user navigates to a different view, so a crashed view doesn't permanently show the fallback after the user navigates away and back

## Implementation details

### ErrorBoundary component (`src/components/ui/error-boundary.tsx`)

```
"use client";
class ErrorBoundary extends React.Component {
  props: { children, fallback?, onError? }
  state: { hasError, error }

  static getDerivedStateFromError(error) → { hasError: true, error }
  componentDidCatch(error, info) → console.error + optional onError callback
  reset() → setState({ hasError: false, error: null })

  render() → hasError ? fallback UI : children
}
```

Fallback UI: centered card with AlertTriangle icon, "Something went wrong" heading, error digest (if present), "Try again" button (calls reset), "Go home" button.

### app-shell.tsx change

Replace the view rendering at line 511-513:
```tsx
// Before:
<div key={view} className="animate-in-fade mx-auto w-full max-w-6xl">
  {renderView()}
</div>

// After:
<div key={view} className="animate-in-fade mx-auto w-full max-w-6xl">
  <ErrorBoundary>
    {renderView()}
  </ErrorBoundary>
</div>
```

## What this does NOT do

- No `react-error-boundary` package (unnecessary — one class component is sufficient)
- No wrapping of sidebar/header/footer (those are stable shadcn components unlikely to crash)
- No nesting of error boundaries inside individual view components (over-engineering)
- No changes to existing `error.tsx` or `global-error.tsx` (they serve different purposes: route-level and root-layout-level)
