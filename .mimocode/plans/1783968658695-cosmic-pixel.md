## Implementation Plan

### Phase 1: Multi-Currency Wallet System (R1 + R11)

**Goal**: Transform the Wallet tab and Dashboard balance card into a multi-currency experience.

#### 1a. API: Add POST /api/intl/currency-wallets (create wallet)

**File**: `turbopay-complete-latest/src/app/api/intl/currency-wallets/route.ts`

- Add `POST` handler to create a single currency wallet
- Accept `{ currency: string }` body
- Validate currency is in `SUPPORTED_CURRENCIES`
- Check wallet doesn't already exist for user+currency
- Create with `balanceMinor: 0`
- Return created wallet

#### 1b. API: Add GET /api/dashboard (multi-currency summary)

**File**: `turbopay-complete-latest/src/app/api/dashboard/route.ts`

- Extend dashboard response to include:
  - `currencyWallets`: array of `{ currency, balanceMinor, status }` for all non-NGN wallets
  - `totalBalanceKobo`: sum of NGN wallet + all currency wallets converted (or just NGN for now)
  - `cardBalanceKobo`: total across virtual cards if applicable

#### 1c. Component: MultiCurrencyBalanceCard

**New file**: `turbopay-complete-latest/src/components/turbopay/parts/multi-currency-balance-card.tsx`

This replaces the current `BalanceCard` on the Dashboard. The Wallet tab keeps its own card.

- Shows default currency (NGN) balance prominently
- Clicking the balance area expands a dropdown/popover showing all currency wallets
- Each row: currency flag/icon + currency code + balance + "Create" button if no wallet
- "Create wallet" triggers POST to create, then refreshes
- Hide/show toggle for total balance
- Currency detection: use `user.country` to set default (NG = NGN, US = USD, GB = GBP, etc.)

**Design decisions**:
- Use a `Popover` (from shadcn/ui) for the currency list — clean, non-disruptive
- Default currency badge in top-right of card
- Total balance shown in default currency with a small "≈" for multi-currency
- Empty wallets show "No wallet — Create one" with a + button

#### 1d. View: Update DashboardView

**File**: `turbopay-complete-latest/src/components/turbopay/views/dashboard.tsx`

- Replace `BalanceCard` with `MultiCurrencyBalanceCard`
- Pass `currencyWallets` from dashboard API
- Update quick actions to include explicit "Fund", "Transfer", "International", "Payment Links" buttons (R3)

#### 1e. View: Update WalletView

**File**: `turbopay-complete-latest/src/components/turbopay/views/wallet.tsx`

- Add a "Currency Wallets" section below the main NGN wallet card
- Grid of currency wallet cards (smaller, compact)
- Each shows: currency code, balance, status
- "Create new wallet" button at the end
- Clicking a currency wallet opens details (balance, recent transactions in that currency)

### Phase 2: Smart Funding Dialog (R4)

**Goal**: Show funding methods based on what providers support in the user's country.

#### 2a. Refactor FundDialog

**File**: `turbopay-complete-latest/src/components/turbopay/views/wallet.tsx` (FundDialog)

- Replace hardcoded Stripe/Paystack/Demo tabs with dynamic method list
- Fetch from `/api/capabilities?category=collection` to get available collection methods
- Group by provider but show user-friendly labels:
  - "Debit Card" (Stripe/Flutterwave)
  - "Bank Transfer" (Monnify/Remita)
  - "USSD" (Paystack/Flutterwave)
  - "Mobile Money" (Onafriq — for non-NG users)
- Each method shows: name, provider badge (optional), estimated time
- Auto-select the fastest method
- Support multiple currencies: if user selects non-NGN wallet, show relevant methods

#### 2b. API: Extend /api/capabilities

**File**: `turbopay-complete-latest/src/app/api/capabilities/route.ts`

- Add `country` and `currency` query params
- Filter capabilities by what's available in that country
- Return with estimated speed (instant, 1min, 5min)

### Phase 4: Transaction PIN Gating (R8)

**Goal**: Only show PIN setup/change when user needs to create or change it.

#### 4a. Settings: Conditional PIN card rendering

**File**: `turbopay-complete-latest/src/components/turbopay/views/settings.tsx`

- Replace always-visible `TransactionPinCard` with conditional rendering:
  - If `user.hasTransactionPin === false`: Show "Set up your transaction PIN" card (prominent, with explanation)
  - If `user.hasTransactionPin === true`: Show only a "Change PIN" button in the Password & PIN section (no input fields until clicked)
- Add a `ChangePinDialog` component that opens when user clicks "Change PIN"
  - Requires current PIN + OTP verification before allowing change
  - Flow: Click "Change PIN" → Enter OTP → Enter new PIN → Confirm

#### 4b. API: Add OTP-based PIN change

**File**: `turbopay-complete-latest/src/app/api/auth/change-pin/route.ts` (new)

- POST: `{ action: "request-otp" }` — sends OTP to email/phone
- POST: `{ action: "change-pin", attemptId, otp, newPin }` — verifies OTP + changes PIN

### Phase 5: Smart Profile Editing with KYC Lock (R10)

**Goal**: Lock KYC-verified fields, allow others with OTP verification.

#### 5a. Define verified fields vs editable fields

Verified by NIN/BVN (locked after KYC verification):
- `fullName` (from NIN)
- `dateOfBirth` (from NIN)
- `gender` (from NIN)
- `stateOfOrigin` (from NIN)

Always editable (with OTP for sensitive ones):
- `username` — editable, no OTP needed (low risk)
- `bio` — editable, no OTP needed
- `avatarUrl` — editable, no OTP needed
- `phone` — editable, requires OTP (account recovery surface)
- `email` — editable, requires OTP (account recovery surface)

#### 5b. Settings: ProfileCard with field locking

**File**: `turbopay-complete-latest/src/components/turbopay/views/settings.tsx` (ProfileCard)

- After KYC verification (tier >= 2):
  - Show `fullName`, `dateOfBirth`, `gender`, `stateOfOrigin` as read-only with a lock icon
  - Tooltip: "This information was verified via NIN/BVN and cannot be changed. Contact support if this is incorrect."
- `username`, `bio`, `avatarUrl` — always editable, save without OTP
- `phone`, `email` — show "Change" button that triggers OTP flow:
  1. Click "Change" → OTP sent to current email/phone
  2. Enter OTP
  3. Enter new value
  4. Confirm with another OTP to new value

#### 5c. API: OTP verification for profile changes

**File**: `turbopay-complete-latest/src/app/api/profile/route.ts`

- Already has PIN-based verification for email/phone changes
- Extend to also support OTP-based verification as an alternative
- Add `otp` and `attemptId` fields to the schema
- If `otp` is provided, verify via OTP service instead of PIN

#### 5d. Component: EditableField with lock state

**New file**: `turbopay-complete-latest/src/components/turbopay/parts/editable-field.tsx`

- Reusable component that shows a field value
- Props: `value`, `label`, `locked`, `lockReason`, `onEdit`, `type`
- If locked: shows value with lock icon + tooltip
- If editable: shows value with edit icon, click to edit inline
- If sensitive (phone/email): shows masked value with "Change" button
