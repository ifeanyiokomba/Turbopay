## Phase 2: RBAC System (Critical)

**Problem:** Legacy `src/` system has only 3 roles (`master_admin`, `admin`, `staff`), no permission constants, no `requirePermission` middleware. The `permissions: string[]` field exists but is never populated or checked.

**Files to create:**
- `src/rbac/permissions.ts` — Define all permission constants (40+ permissions matching TurboCore's patterns)
- `src/rbac/roles.ts` — Define 10 admin roles with permission mappings
- `src/rbac/middleware.ts` — `requirePermission(permission)` middleware

**Files to modify:**
- `src/admin/auth/auth.service.ts`
  - Add 10 role types to `AdminUser.role` union
  - Map roles to permission sets in `hasPermission()`
  - Ensure `SUPER_ADMIN` gets all permissions
- `src/server.ts` (lines 274-307)
  - Add `requirePermission` enforcement in route handler
  - Check `req.user.permissions` against route's required permission
- `src/api/routes.ts`
  - Add `permission` field to `Route` interface
  - Add permission requirements to all 40+ admin routes

**Permission categories (from TurboCore):**
- `wallet:view`, `wallet:fund`, `wallet:transfer`
- `tx:view`, `tx:process`, `tx:reverse`, `tx:refund`
- `kyc:view`, `kyc:approve`, `kyc:reject`
- `admin:manage:users`, `admin:manage:roles`, `admin:manage:fees`
- `admin:view:audit`, `admin:export:audit`
- `provider:view`, `provider:manage`, `provider:health`
- `compliance:view`, `compliance:manage`
- `system:view:health`, `system:manage:config`
- `bill:view`, `bill:pay`
- `card:view`, `card:manage`
- `notification:send`, `notification:manage`
- `support:view`, `support:manage`

## Phase 3: Email Delivery (Critical)

**Problem:** Email service is a stub. `sendAdminInvite()` and `sendPasswordResetEmail()` exist but are never called from auth flows. Auth services don't have email service injected.

**Files to modify:**
- `src/services/email-service.ts` (line 133)
  - Uncomment the Resend API call
  - Add proper error handling
  - Make API key optional (gracefully degrade if not configured)

- `src/admin/auth/auth.service.ts`
  - Accept `EmailService` as constructor dependency
  - In `inviteAdmin()`:
    - Call `emailService.sendAdminInvite(email, firstName, invitedBy, role, jobTitle)`
    - Return the `tempPassword` in the response (or generate an invite URL)
  - In `requestPasswordReset()`:
    - Call `emailService.sendPasswordResetEmail(email, firstName, resetUrl)`
    - Generate and include a proper reset URL
  - In `completeOnboarding()`:
    - Fix the bug: actually hash and set the new password

- `src/auth/customer-auth.service.ts`
  - Accept `EmailService` as constructor dependency
  - In `requestPasswordReset()`:
    - Call `emailService.sendPasswordResetEmail(email, firstName, resetUrl)`

- `src/main.ts` (lines 135-136, 220-227)
  - Pass `emailService` to `AdminAuthService` and `CustomerAuthService` constructors

**Email templates to verify/update:**
- `admin_invite` — Include temp password and onboarding link
- `password_reset` — Include reset URL with token
- `otp` — For transaction verification

## Phase 4: Webhook Handlers for Mobile Money (High)

**Problem:** No provider-specific webhook handlers for mobile money. MTN and M-Pesa don't validate signatures (by design), but the generic handler needs to properly process their callbacks.

**Files to verify/modify:**
- `src/services/webhook-handler.ts`
  - Add mobile money event types: `mobile_money.collection.success`, `mobile_money.disbursement.success`
  - Register handlers for each mobile money provider's callback format
  - Ensure MTN's polling-based status check is handled
  - Ensure M-Pesa's STK Push callback is parsed correctly

- `src/adapters/mtn-momo.adapter.ts`
  - Verify `validateWebhook()` handles MTN's callback format
  - Verify `parseWebhookEvent()` extracts correct fields
  - Add polling logic for async collection status

- `src/adapters/mpesa.adapter.ts`
  - Verify `validateWebhook()` returns true (M-Pesa has no header sig)
  - Verify `parseWebhookEvent()` handles STK Push ResultCode/CallbackMetadata

- `src/adapters/paga.adapter.ts`
  - Verify reverse-API routes work correctly
  - Ensure `processPayment()` and `processDisbursement()` handle callbacks

**Files to create (if needed):**
- `src/api/webhooks/mtn-momo/route.ts` — Dedicated MTN webhook endpoint
- `src/api/webhooks/mpesa/route.ts` — Dedicated M-Pesa webhook endpoint
- `src/api/webhooks/airtel-money/route.ts` — Dedicated Airtel webhook endpoint
- `src/api/webhooks/smartcash/route.ts` — Dedicated SmartCash webhook endpoint
